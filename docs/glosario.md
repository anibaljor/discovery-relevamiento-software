# Glosario

| Término (ES) | Término (EN) | Definición |
|--------------|-------------|------------|
| Actor | Actor | Persona, rol o sistema externo que interactúa con el sistema. |
| Alcance | Scope | Lo que el proyecto/producto incluye. Se define junto con lo que queda *fuera de alcance*. |
| Analista de negocio | Business Analyst (BA) | Rol que identifica necesidades del negocio y recomienda soluciones. |
| Análisis funcional | Functional specification | Documento que detalla el comportamiento funcional del sistema (término muy usado en Hispanoamérica). |
| As-is / To-be | As-is / To-be | Situación o proceso actual / situación o proceso futuro deseado. |
| Backlog | Product Backlog | Lista priorizada y viva de trabajo pendiente del producto. |
| BRD | Business Requirements Document | Documento de requisitos de negocio. |
| Caso de negocio | Business Case | Justificación económica de un proyecto. |
| Caso de uso | Use Case | Descripción de cómo un actor usa el sistema para lograr un objetivo. |
| Criterio de aceptación | Acceptance criteria | Condiciones verificables que una funcionalidad debe cumplir para considerarse aceptada. |
| Criterio de ajuste | Fit criterion | En Volere, medida objetiva para comprobar que un requisito se cumple. |
| Definition of Done (DoD) | Definition of Done | Acuerdo del equipo sobre cuándo un ítem está terminado. |
| Definition of Ready (DoR) | Definition of Ready | Acuerdo sobre cuándo un ítem está listo para empezar a desarrollarse. |
| Discovery | Discovery | Etapa (o actividad continua) para entender el problema, los usuarios y definir qué construir. |
| Elicitación / relevamiento | Elicitation | Obtener y descubrir requisitos de stakeholders y otras fuentes. |
| Épica | Epic | Historia grande que se divide en historias más pequeñas. |
| Especificación | Specification | Documento que describe requisitos de manera precisa. |
| Fuera de alcance | Out of scope | Lo que explícitamente no se incluye. |
| Gherkin | Gherkin | Lenguaje *Dado/Cuando/Entonces* (*Given/When/Then*) para escribir criterios de aceptación. |
| Historia de usuario | User Story | Descripción corta de una necesidad desde la perspectiva del usuario. |
| Interesado / parte interesada | Stakeholder | Persona o grupo que afecta o es afectado por el proyecto. |
| INVEST | INVEST | Criterios de calidad de una historia: Independiente, Negociable, Valiosa, Estimable, Pequeña, Testeable. |
| Lenguaje ubicuo | Ubiquitous language | En DDD, vocabulario común entre negocio y desarrollo. |
| MVP | Minimum Viable Product | Versión mínima que permite aprender o entregar valor con el menor esfuerzo. |
| Minuta | Meeting minutes | Registro escrito de lo tratado y acordado en una reunión. |
| PRD | Product Requirements Document | Documento de requisitos de producto. |
| Product Owner | Product Owner | En Scrum, responsable de maximizar el valor del producto y gestionar el backlog. |
| Prototipo | Prototype | Representación preliminar de la solución para explorar o validar. |
| RACI | RACI | Matriz de responsabilidades: Responsable, Aprobador, Consultado, Informado. |
| Regla de negocio | Business rule | Política o restricción del negocio que el sistema debe respetar. |
| Requisito funcional | Functional requirement | Lo que el sistema debe hacer. |
| Requisito no funcional / atributo de calidad | Non-functional requirement / Quality attribute | Cómo debe comportarse el sistema (rendimiento, seguridad, usabilidad, etc.). |
| Restricción | Constraint | Limitación impuesta a la solución (tecnología, presupuesto, normativa, plazo). |
| RFI / RFP / RFQ | Request for Information / Proposal / Quotation | Solicitudes formales de información, propuesta o cotización a proveedores. |
| SOW | Statement of Work | Documento contractual que define el trabajo a realizar. |
| SRS | Software Requirements Specification | Especificación de requisitos de software. |
| Story map | User Story Map | Mapa bidimensional de historias según el recorrido del usuario. |
| Supuesto | Assumption | Algo que se da por cierto sin haberlo verificado. |
| Trazabilidad | Traceability | Capacidad de seguir un requisito desde su origen hasta su implementación y prueba. |
| Validación | Validation | Confirmar que los requisitos reflejan las necesidades reales (¿construimos lo correcto?). |
| Verificación | Verification | Confirmar que el producto cumple lo especificado (¿lo construimos correctamente?). |
| Visión y alcance | Vision and Scope | Documento que acuerda problema, objetivos y límites del proyecto. |
