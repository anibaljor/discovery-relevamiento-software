# Inception Deck

> Basado en Jonathan Rasmusson, *The Agile Samurai* (2010). Se trabaja en uno o varios talleres con cliente y equipo. Cada ejercicio se resume en una diapositiva o lámina.

**Proyecto:** — **Fecha:** — **Participantes:**

---

## 1. ¿Por qué estamos aquí?
Propósito del proyecto en pocas frases. ¿Quién es el cliente? ¿Por qué se toma la decisión de hacerlo?

## 2. Elevator pitch
> Para **[clientes objetivo]**
> que **[necesidad u oportunidad]**,
> el **[nombre del producto]**
> es un **[categoría de producto]**
> que **[beneficio clave, razón para comprarlo/usarlo]**.
> A diferencia de **[alternativa principal]**,
> nuestro producto **[diferenciador]**.

## 3. Diseñar la caja del producto
Si el producto se vendiera en una caja: nombre, imagen, eslogan, 3 beneficios principales (beneficios, no funcionalidades).

## 4. La lista de lo que NO es
| ES ✅ | NO ES ❌ | AÚN NO SABEMOS ❓ |
|-------|---------|-------------------|
| | | |

## 5. Conocer a los vecinos
Mapa de la "comunidad" del proyecto: todas las personas y equipos con quienes habrá que interactuar (seguridad, infraestructura, legales, otros proveedores, usuarios, etc.).

## 6. Mostrar la solución
Arquitectura de alto nivel: componentes, integraciones, tecnologías candidatas.

## 7. ¿Qué nos quita el sueño?
Riesgos principales y cómo podríamos mitigarlos.

| Riesgo | ¿Se puede controlar? | Mitigación |
|--------|--------------------|-----------|
| | | |

## 8. Dimensionar
Estimación gruesa del tamaño: ¿semanas, meses, un año? ¿Cuántos releases?

## 9. Qué se negocia (sliders de trade-offs)
Ubicar cada fuerza en una escala: no todas pueden ser máximas. Ninguna dos en el mismo nivel.

```
                  Negociable ◄──────────────► Innegociable
Alcance completo    [ ][ ][ ][ ][ ]
Presupuesto         [ ][ ][ ][ ][ ]
Fecha               [ ][ ][ ][ ][ ]
Calidad             [ ][ ][ ][ ][ ]
---- otros posibles ----
Facilidad de uso    [ ][ ][ ][ ][ ]
Rendimiento         [ ][ ][ ][ ][ ]
Seguridad           [ ][ ][ ][ ][ ]
```

## 10. ¿Qué va a costar?
Equipo necesario, duración, costo estimado y supuestos.

## Variante: Lean Inception (Paulo Caroli)

Taller de ~5 días orientado a definir un MVP. Agenda típica:

| Día | Actividades |
|-----|------------|
| 1 | Kick-off, visión del producto, es / no es / hace / no hace, objetivos del producto |
| 2 | Personas, brainstorming de funcionalidades |
| 3 | Revisión técnica, de negocio y de UX de cada funcionalidad; journeys de usuario |
| 4 | Secuenciador de funcionalidades (qué entra en cada ola/incremento) |
| 5 | Canvas MVP y showcase final |

**Canvas MVP:** propuesta del MVP, personas segmentadas, journeys, funcionalidades, resultado esperado, métricas para validar hipótesis de negocio, costo y cronograma.
