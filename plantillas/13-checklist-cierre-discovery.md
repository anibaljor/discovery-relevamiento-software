# Checklist de cierre de discovery

> ¿Estamos listos para estimar con confianza y empezar a construir? Revisar con el equipo y con el cliente.

## Problema y objetivos
- [ ] El problema está descrito en términos de negocio, no de solución.
- [ ] Hay objetivos de negocio con métricas y valores objetivo.
- [ ] El patrocinador aprobó la visión del producto.

## Stakeholders y usuarios
- [ ] Están identificados todos los stakeholders (incluidos seguridad, legales, TI, soporte).
- [ ] Hablamos con usuarios reales de cada perfil (no solo con intermediarios).
- [ ] Está claro quién decide y quién es el referente del día a día (y su disponibilidad).
- [ ] Hay una matriz RACI para las decisiones clave.

## Alcance
- [ ] Están definidas las características principales y priorizadas.
- [ ] El MVP / primer release está acordado.
- [ ] **El "fuera de alcance" está escrito y aceptado.**
- [ ] Están identificadas las integraciones con otros sistemas.
- [ ] Está definida la estrategia de migración de datos (o se acordó que no hay).

## Detalle y calidad
- [ ] Los requisitos del primer release tienen criterios de aceptación verificables.
- [ ] Hay prototipos validados con usuarios para las pantallas/flujos principales.
- [ ] Los requisitos no funcionales críticos son medibles (rendimiento, disponibilidad, seguridad, accesibilidad).
- [ ] Las reglas de negocio importantes están documentadas.
- [ ] Hay un glosario compartido.

## Técnica
- [ ] Hay una arquitectura de alto nivel.
- [ ] Se identificaron los riesgos técnicos y, si hacía falta, se hicieron pruebas de concepto.
- [ ] Están definidos los ambientes y la infraestructura (nube/on-premise, responsable).

## Riesgos, supuestos y pendientes
- [ ] Los riesgos principales tienen una mitigación.
- [ ] Los supuestos están escritos y el cliente los conoce.
- [ ] Las preguntas abiertas restantes no bloquean el inicio (o tienen responsable y fecha).

## Acuerdo
- [ ] La estimación está expresada como rango, con supuestos explícitos.
- [ ] Hay un roadmap / plan de releases.
- [ ] Está acordado el proceso de gestión de cambios.
- [ ] Están definidos los criterios de aceptación del proyecto / de cada entregable.
- [ ] El cliente aprobó formalmente los entregables del discovery.
